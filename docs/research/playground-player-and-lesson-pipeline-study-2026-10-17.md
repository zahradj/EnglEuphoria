# Playground player and lesson pipeline: study for the Academy player v2 (2026-10-17)

> Owner request (2026-10-17): "Check how the Playground hub player is working, and how it generates lessons. What is the process, and try to adapt the important steps."
> Method: read-only study of the repo at branch `claude/confident-pascal-0ui2i4`. The Playground was only **read**; nothing was edited, imported or moved (hub separation). Paths are repo-relative; "L" numbers are line numbers as of this commit (`99b279e7`).
> Evidence labels: **read** = I opened the file; **inferred** = concluded from code I read; **not verified** = I could not check (no database, no browser, no CI logs).

## 0. Summary (read this first)

1. **The Playground has one real engine and many data files.** A lesson is a plain `Scene[]` array of JSON-like objects (`unit1/scenes.ts`, 18,305 lines). One dispatcher (`unit1/SceneRenderer.tsx` L247-L437, a `switch` on `scene.kind`, `default: return null`) maps each `kind` to a component file in `unit1/scene-components/` (about 130 kinds). Three lesson players (`PlayUnitLesson.tsx` 928 lines, `PlayWelcomeTownLesson.tsx` 879 lines, plus the creator/`scene-player` path) drive them.
2. **The process is gate-driven, not tool-driven.** There is no lesson generator CLI for scene lessons. A lesson is written by the AI from skills (`generate-lesson` -> `smart-lesson-architect` -> `activity-pattern-library` -> `lesson-variety-engine` -> `lesson-quality-gate`), then **vitest "deploy gate" tests** reject bad lessons (`lessonVariety`, `recallWarmup`, `calmBackground`, `voicePolicy`, `a1LessonLength`, `sceneMirrorFuzz`, `classroomHygiene`...). Vercel runs those tests inside `npm run build:vercel` (`package.json` L11), so a failing rule blocks the deploy.
3. **The most valuable thing in the Playground is its live-class robustness stack**, born from real crashes: `SceneCrashGuard` (retry, safe mode, card; `SceneCrashGuard.tsx` L21-L22), `useSyncedState` + `reconcileSyncedState` (`sceneActivitySync.ts` L68-L100), scene-scoped state, a fuzz test that renders **every scene of every lesson** as a hostile student mirror (`sceneMirrorFuzz.test.tsx`), and structural hygiene tests (`classroomHygiene.test.ts`).
4. **The Academy v2 player already took the right concepts** (plan section 2.5): scene registry with `validate`/`spoken`, a pure reducer engine, game phases, game state, an fx kit, a crash boundary, DOM-path replay bridge, and it already goes **beyond** the Playground in places (art-review register, speaking ladder, blueprint-driven validator, seeded randomness, quest layer).
5. **But the Academy copied the shape, not the safety net.** Missing or weaker: crash guard with retry/safe-mode/logging (v2 `SceneBoundary.tsx` is 9 lines, no log); a mirror-fuzz test; synced state (v2 uses only the DOM-path click replay that the Playground itself replaced for most kinds); a per-activity checklist log feeding the teacher report (the old deck had `useAcademyActivityLog`, v2 never calls it); a lesson scaffold; a variety/profile gate (old `lessonProfiles.ts` is in the old deck).
6. **Surprise 1 (hub-separation breach):** `src/academy-player-v2/classroom/EmbeddedPlayerLesson.tsx` L5 **imports `getDomPath`/`getElementAtPath` from the Playground** (`@/content/playground-library/unit1/scenePathSync`). The only isolation test covers `src/curriculum/academy` only (`src/curriculum/academy/__tests__/isolation.test.ts`), so nothing caught it. Also `docs/hub-separation.md` rule 6 asks the owner where shared `speak()` lives; v2 correctly avoids the Playground `speak()` (uses `academy-deck/audio`).
7. **Surprise 2 (gate not wired):** the Vercel deploy gate runs `vitest run src/content/playground-library src/academy-games ...` (`package.json` L11). It does **not** run `src/academy-player-v2`, `src/academy-deck` or `src/curriculum/academy`, and does not run `npm run typecheck:academy-player`. CLAUDE.md calls `artReview.test.ts`, `gameQuality.test.ts` "deploy gates", but they only run in the CI workflow (`ci.yml` runs all tests, `test:unit`). So an Academy rule can fail without blocking a Vercel build. (Whether CI is a required check on `main` is **not verified**.)
8. **Surprise 3:** the Playground has **no art-review register**. CLAUDE.md says "same as the Playground", but I found nothing like `ART_REVIEW` there; its art check is a skill-level eye check (`lesson-quality-gate` "re-open every background image") plus a few tests (`soundPictures.test.ts`, `check-homework-art.mjs`). The Academy `artReview.ts` + `artReview.test.ts` is already **stronger** than the Playground. Keep it.
9. **Do not copy:** hearts (lose-lives), per-lesson route files (about 150 near-identical `PlayUnitNLessonM.tsx` wrappers), the 18k-line single `scenes.ts`, mascots, stickers-for-everything, procedural WebAudio beeps as the main sound, the DB-row-per-lesson hand-off for Academy (hub rule: do not touch legacy rows).
10. **Recommended order:** (1) fix the two breaches (own `scenePathSync`, wire the Academy tests into the deploy gate and typecheck); (2) crash guard v2 + mirror fuzz; (3) `npm run academy:new-lesson` scaffold; (4) per-activity checklist log in v2; (5) synced state for the games that need it; (6) lesson profile/variety gate; (7) content-format version + registry meta; (8) bake/audit workflow parity for Academy audio and art.

### A2. Scene contract, registry, validation (read)

- **Contract:** every scene is `{ id, kind, bg, ...kind fields }` (`Scene` union in `unit1/scenes.ts`). Every component receives `{ scene, onNext, onWin(gem), onLose, sync? }` (see the `case` lines in `SceneRenderer.tsx` L269-L436). `onWin(gem:boolean)` is the only scoring signal the player sees.
- **Registry:** the `switch` itself (not a map). Adding a kind means 4 edits: the `Scene` union, a component file, the `case`, and `SCENE_KINDS` in `unit1/sceneValidator.ts` L21 (a second, independent list; `generate-lesson` section 4 step 2 warns "easy to miss"). **Weakness:** two lists that can drift.
- **Validator:** `validateLesson(scenes, ctx)` (`sceneValidator.ts` L70) uses zod for shape and checks: unique ids, unknown kind (L100), canonical cast only (`pip, mia, bella, willow, leo, teacher, narrator`), letter/target integrity for basket/dash, song needs a url or prompt, length 15-32 scenes, banned placeholders, vocab recycled >= 3 times. `sceneValidator.test.ts` holds a `LESSONS` array (L78) that every new lesson must be added to **by hand**.
- **Dispatcher extras:** `displayScene()` (`stageLabel.ts`) rewrites labels; `TeacherTip` overlay shows the scene's `teacher` field to the teacher only (SceneRenderer L225-L245).
- **Academy comparison:** v2 has a better registry (`scenes/registry.ts` map of `{view, spoken, validate, art}`) and a blueprint-aware validator (`engine/validateScript.ts`, 25 lines: blueprint exists, minutes sum to 60, criteria trained, parts monotone, unknown kinds, each module's `validate`). It runs in `lessons.test.ts` for every registered lesson, so there is no second list to forget.

### A3. Phase machine, scoring, game feel (read)

- **There is no shared phase machine in the Playground.** Each game component owns its own `useState` for intro/play/win/lose. The player only sees `onWin(gem)` and `onLose()`. (The Academy `engine/gamePhases.ts` is therefore a **cleaner** version of the idea.)
- **Scoring at lesson level** (`PlayUnitLesson.tsx`): `hearts` (start `MAX_HEARTS`, L141), `gems` (L142). `loseHeart` logs a wrong try, and at 0 hearts refills after 400 ms (L683-L690): **hearts never end the lesson** (soft). `registerWin(didGem)` adds a gem. The gem total uses an **exclude list** `NON_GEM_KINDS` (L761) instead of an include list; the comment (L744-L760) explains the include list had silently undercounted ("9/6").
- **Game-feel kit** `unit1/scene-components/gameFx.tsx` (210 lines): `LivingBg` (looping bg video with a still fallback), `CalmBg` (blur + veil behind floating pieces), `useBursts`/`Bursts` (emoji particles), `FloatText`, `Hopper` (squash and stretch), `useShake`, `idleFloat`. Enforced by `calmBackground.test.ts` (a hand list `NEEDS_CALM_BG` of files that must render `<CalmBg`).
- **SFX** `unit1/sfx.ts` (91 lines): eight **procedural WebAudio tones** (`pop, click, match, wrong, reveal, gem, ring, whoop`), relayed to the other screen in a live class so both hear it together.
- **Academy comparison:** v2 has `engine/gameState.ts` (score, combo x2/x3, tries, no timer), `engine/gamePhases.ts`, `fx/` with a `SceneFx` object passed to scenes (`types.ts` L68-L84, calm-aware), a quest/loot/rank layer. **Gap:** no `CalmBg`-style test that lists floating-piece games; v2 uses `calmPlate` in the shell for every scene (`LessonPlayer.tsx`), which is simpler and safe.

### A4. Audio (read)

- `unit1/audio.ts` (824 lines): `speak(text, character)` L574. Order: pre-baked clip `/audio-cache/<hash>.mp3` (`cacheFileName` L294, fetched L300), then IndexedDB cache (L189-L193), then the `elevenlabs-tts` edge function by plain `fetch` (L339; the file header explains `supabase.functions.invoke` corrupts the audio body). Policy imports: `approvedVoiceId, normalizeForSpeech, isShortLine` from `@/lib/speechPolicy` (L8).
- No browser voice: `playFallback` only warns and stays silent (L403-L405).
- **Live class:** the speaking side relays each line to the other screen with a network lead so both start together (`setSpeechRelay`, `setSpeechRelayLead`, `playRelayedSpeech`, `setSpeechDedupe`, ping/pong latency measurement in `PlayUnitLesson.tsx` L319-L369).
- **Bake pipeline:** `scripts/generate-voice-cache.mjs` walks every `LESSON_*_SCENES` export through per-kind **extractors** (only kinds whose spoken text is verbatim from scene data); the rest fall back to live generation. `bake-voice.yml` runs on any change to `scenes.ts`/`homework.ts`, records only missing clips with the repo secret `BAKE_SERVICE_KEY`, commits to `public/audio-cache/`. `--audit` prints risks; `voice-audit.yml`, `voice-phoneme-audit.yml` (phoneme recogniser vs dictionary) and `voice-retake.yml` (picks the best of several takes for 1-2 word clips) are one-off audit tools triggered by pushing a run file.
- **Academy comparison:** already parallel and good: `academy-voice-lines.mjs` -> `bake-academy-voice.mjs --audit` -> `academy-voice.yml` -> `public/academy-audio/`, `services/voice.ts` (silent if no clip, mute switch). **Gap:** no phoneme audit or retake workflow for Academy clips (not verified whether the Playground ones were ever run on Academy lines; they read `public/audio-cache` only), and no extractor-vs-renderer drift test (the Academy `spoken()` per module is the single source, which is the better design).

### A6. Crash guard and classroom sync (read)

- **`SceneCrashGuard.tsx`** (119 lines) wraps each scene (`PlayUnitLesson.tsx` L819): crash 1 -> quiet remount ("Reconnecting..."), crash 2 -> **safe mode** (children get `safeMode=true`, live sync switched off), crash 3 -> card with Reload and, for whoever can navigate, Skip. Every crash is logged to `system_errors` with scene id, kind, side and mode (`lib/classroomCrashLog.ts`). Outermost net: `ClassroomSceneErrorBoundary` in MainStage (per the skill; not opened).
- **Roles:** `role` = teacher or student, `roomId`; `canNavigate = !isSynced || role === 'teacher'` (L145). The teacher owns the scene index (broadcast over `whiteboardService`), the student follows; `interactionUnlocked` gate ("Let student interact"), `ALWAYS_UNLOCKED_SCENE_KINDS` (hands-on kinds), student can ask the teacher to advance (`sendSceneAdvanceRequest`). The DB copies of index and lock are for **recovery only** (comment L40-L60 explains a ping-pong bug).
- **Three sync mechanisms, in order of preference:**
  1. `useSyncedState(sync, initialObject)` (`sceneActivitySync.ts`): ONE JSON object per scene, authority broadcasts the full object, the mirror renders from the latest snapshot; `reconcileSyncedState` patches missing or wrong-typed fields with the scene's defaults so a partial snapshot can never read `undefined`; hand-over keeps the activity where it was (L110-L125); `SHARED_PLAY_KINDS` lets both screens drive at once (leader runs the automatic sequences).
  2. `useSyncedSceneState` (`unit1/useSyncedSceneState.ts`, 47 lines): older last-write-wins channel.
  3. DOM-path click replay (`unit1/scenePathSync.ts`): record the child-index path of a click and `.click()` the same path on the other side. Documented as fragile (the student's own lock overlay broke it) and **replaced kind by kind** (Welcome Town 15/22 kinds, Pre-A1 39/63 per `generate-lesson` section 4c).
- **Rules** (`.claude/skills/classroom-sync-robustness`): one state object, typed defaults, no `Set`/`Map` in state, guard indices, `Math.random()` only on the authority (or part of the state), gate self-driving timers on `!isRemoteMirror`.
- **Tests:** `sceneMirrorFuzz.test.tsx` renders every scene of every `LESSON_*_SCENES` export (and every game lesson) as a student mirror with hostile and mid-interaction snapshots; `SceneCrashGuard.test.tsx`; `sceneActivitySync.test.tsx` (L13-L90: defaults, hand-over, scene-scoped state, remount, persistent crash); `sharedPlay.test.tsx`; `classroomHygiene.test.ts` (source scans, e.g. interaction is never re-locked on scene change).
- **Academy comparison:** `shell/SceneBoundary.tsx` (9 lines) = crash 1 shows the card; no retry, no safe mode, no log. Bridge = DOM-path replay only (`classroom/EmbeddedPlayerLesson.tsx` L47-L88) with `data-av-local` opt-out for private panels, a nice touch. `setInteractionUnlocked` is a no-op (L38) so the teacher cannot pause the student (inferred). v2 scenes are deterministic via `seed` (no `Math.random` in non-test v2 code: grep clean), which removes the Playground's worst desync cause by design.

## B. The generation process, step by step

There is no single command. The pipeline is: **skills (AI judgement) -> data files -> registries -> automatic gates -> bakes -> DB row -> preview**. Legend: **AI** = Claude does it; **Owner** = needs written approval; **Auto** = a test, script or workflow does it.

| # | Step | What happens | Where (read) | Who |
|---|---|---|---|---|
| 1 | **Orient: blueprint and slot** | Query the pre-seeded `curriculum_lessons` row for the slot (unit, lesson, title, objective); query the whole map before renaming a unit's topic. Each unit has 6 (then 7) slots with a house role: L1 set A, L2 set B, L3 twist + combination, L4 pure review (no new art), L5 story, L6 capstone, L7 Boss Test. | `generate-lesson` section 3; `playground-library-lesson-builder` section 16 (canonical map); `docs/playground-lesson-blueprint.md` (22-slide skeleton, 22-25 pages, 30 min, mastery gate >= 80%, leaderboards forbidden) | AI |
| 2 | **Objective and knowledge graph** | Performance objective ("can greet a partner and say their name"), three questions (what is new, what is reviewed, what shows evidence), new knowledge about 20-30%, no orphan topic, 10-step flow (welcome, review, new, guided, interactive, story, speaking, assessment, review, home challenge). | `playground-curriculum-engine` (L139-L247 checklist) | AI |
| 3 | **Micro-skills and activity purposes** | Decompose the objective, pick a purpose per activity (recognition, matching, manipulation, retrieval, speaking, reading, creative, assessment), variation engine, gamification rules, difficulty ladder, anti-repetition validator and a "reject weak lessons" list. | `smart-lesson-architect` sections 4-8, 18-19 | AI |

**What is automated vs manual (summary):** automated = validators, variety/recall/voice/story/art-size tests, the mirror fuzz, voice bake, art fetch/bake, build gate, preview gating. Manual (AI judgement) = objective design, activity choice, research, scene text, picture review, semantic pass, DB update. Owner approvals = scenarios and storyboard rows for any video, key pictures, the preview review, merge to `main` (publishing).

**Unautomated and error-prone in the Playground (do not reproduce):** the 6-file registration, the duplicated kind lists, the hand-maintained `NEEDS_CALM_BG` and `LESSONS` arrays, hand-set `GRANDFATHERED`, the per-lesson route wrappers, and extractor-covered vs uncovered voice kinds.

### What NOT to copy

- **Hearts / lose-lives**, countdown timers, star ratings per stop, leaderboards or rankings (blueprint section 1 forbids leaderboards even for the Playground), pets and mascots (Pip, Biscuit), stickers as a reward, emoji particles (`BURST_GLYPHS` are emoji: stars, hearts, confetti) and emoji in UI. Academy keeps sparks, XP and quiet rank.
- **Procedural WebAudio beeps as the SFX bank** (`sfx.ts` square/sawtooth tones): childish and harsh; use short recorded or designed clips (plan section 2.5 already says so).
- **Per-lesson route wrapper files** and one huge data file: use `/academy-lesson/:id` and one file per lesson (already so).
- **Two parallel player families** and two kind lists.
- **`Math.random` in scenes**; keep seeded.
- **Include-list of "gem kinds"**: the Playground's own comment says the exclude-list is safer; the Academy derives gems from `SceneResult` instead.
- **The DB-row-per-lesson activation** (`curriculum_lessons` UPDATE) for Academy until the owner decides how the Academy roadmap reaches the database.
- **Browser voice fallbacks** (the Playground left a `playFallback` stub; Academy must not even have one).
- **The Playground's one-line `speak()` relay stack** until live-class audio sync is actually needed in Academy (one-to-one: the teacher's own voice is on the video call; I did not verify how Academy audio behaves for the second screen).
